### Descripcion

```markdown
## Resumen
Implementa cache-aside de snapshot de ruta por sesion para evitar reconstruir desde BD en cada carga de mapa de guia/turista.

## Cambios principales
- Se implementa snapshot cacheado por sesion con clave `tour:session:{id}:route_snapshot`.
- Se incorpora lectura cache-aside en `mapa_guia` y `mapa_turista_anonimo`.
- Se agrega invalidacion automatica en eventos clave:
  - `post_save/post_delete` de `SesionTour`
  - `post_save/post_delete` de `Ruta`
  - `post_save/post_delete` de `Parada`
- Se añade configuracion de cache en `config/settings.py`:
  - `USE_REDIS_CACHE`
  - `REDIS_CACHE_URL`
  - `ROUTE_SNAPSHOT_CACHE_TTL`
- Se agrega dependencia `django-redis`.
- Se añaden tests especificos para:
  - cache miss -> construye y guarda
  - cache hit -> no reconstruye
  - invalidacion al cambiar parada actual

## Archivos clave
- `tours/services.py`
- `tours/views.py`
- `tours/signals.py`
- `tours/apps.py`
- `config/settings.py`
- `tours/tests/test_s2_2_29_route_cache.py`
- `requirements.txt`
- `README.md`
- `TASKS.md`
- `.env.local.example`

## Como validar
1. Ejecutar tests especificos:
   - `python manage.py test tours.tests.test_s2_2_29_route_cache -v 2`
2. Ejecutar suite completa:
   - `python manage.py test -v 1`
3. Validacion manual en Redis:
   - Generar snapshot con carga de mapa o `services.get_route_snapshot(...)`
   - Consultar clave fisica (con prefijo de version django-redis) y TTL

## Riesgos/Notas
- `TTL = -2` en Redis implica clave inexistente (expirada, invalidada o consulta de clave sin prefijo fisico).
- Logs de checkpoint de PostgreSQL son comportamiento normal y no indican fallo de cache.
```
